# Kernary Code

Terminal-native multi-agent coding runtime.

> `kernary-code` is not published to npm yet. This directory contains the prepared launcher package for the first release; build and run the repository source for now.

```bash
git clone https://github.com/zhaoxuya520/kernary-code.git
cd kernary-code
cargo build --release --locked -p harness-cli --bin kernary
./target/release/kernary --help
```

On first launch, use `/connect` and `/model`. Kernary refuses normal and non-interactive work with `MODEL_NOT_CONFIGURED` until a real or local model is ready; the published default never runs the deterministic test provider.

The transcript-first TUI keeps internal telemetry out of the conversation, presents project/model/context/agent state in a responsive semantic header, and uses a floating `/` command palette plus distinct normal, setup, and secure-key composer states. PgUp/PgDn scroll the transcript without disturbing input history. The editor also supports Unicode cursor movement, Home/End, Delete/Backspace, common Ctrl line-editing shortcuts, and bracketed paste.

Normal TUI conversations run in a background execution lane, so network/model/tool loops never block keyboard input or redraws. Enter immediately acknowledges submission; streamed text deltas coalesce into one continuously growing assistant paragraph instead of one labelled line per token. Bounded reasoning summaries, Agent lifecycle, tool activity, file reads/writes, byte counts, process exits, and undo availability update live without exposing private chain-of-thought. Setup results become color-coded, eight-second footer notices and disappear on the next conversational turn instead of polluting durable transcript history.

Use `/provider add` for a named custom endpoint (name → protocol → URL → secure key → model discovery → default selection). Text providers and the selected default model are user-global: successful `/provider switch` and `/model` operations atomically update `providers.toml` and `model.json` in the Kernary user configuration directory, so new windows, projects, and resumed sessions inherit the same default. The switch picker reloads the merged catalog every time and lazily registers providers added by another window. `/provider key [provider-id]` uses the secure input lane to replace a key without exposing either value; providers with discovery endpoints must validate the new key before commit, and failures restore the previous key. An explicit `--model provider/model` remains a one-launch override. Legacy project `kernary.providers.toml` files remain readable and migrate when selected. The protocol page supports OpenAI Responses, OpenAI Chat Completions, and Anthropic Messages with protocol-correct endpoints, discovery formats, and authentication headers. `/vector setup` manages a global embedding-provider catalog: Voyage AI and Jina AI need only a key and use built-in model IDs; named custom providers accept multiple model IDs. Every selected model must return a valid numeric embedding before it can be activated. Use `/vector provider` and `/vector model` for two-level switching. Every project performs a startup health check while keeping memory/vector data project-local. `/language en|zh-CN|zh-TW|ja` switches the customized language pack.

Interactive provider, model, vector, and session choices use dedicated selection pages: move with Up/Down, confirm once with Enter, and return with Esc. Wizard diagnostics remain transient; only the final result is added to the conversation. `clear`, `cls`, and `/clear` are local viewport commands and never require a configured model.

Shift+Tab changes permission mode silently. The active mode is shown only as a color-coded lower-left badge instead of appending configuration lines to the transcript.

Kernary includes 30 sleeping-by-default agents. Fifteen full-stack specialists cover Product, UX, Product Design, Design Systems, Frontend, Backend, API contracts, Database/SQL, Quality, Accessibility, Platform/DevOps, SRE/Observability, Technical Writing, Localization, and Product Analytics. `/team adaptive <1..4> <objective>` adds only keyword-relevant specialists; a full-stack/complete-product objective builds a 24-node specialist delivery DAG and replaces generic coders with frontend/backend owners.

Running `kernary` creates a new project-local session. Use `kernary -c`, `kernary -r [id-or-title]`, or `/session` to resume/switch only within the current folder. Session history remains project-local, while the default text provider/model is user-global. The first user turn creates an immediate local fallback title; after the first complete answer, the current provider/model runs a background, tool-free, output-bounded title job and atomically replaces that fallback. Failures keep the local title, and a manual `/session rename` is never overwritten. The immutable transcript survives context compaction. Permission levels are `manual`, `edit`, `auto`, `full`, and explicitly confirmed `bypass`. Project-private `.harness/agent.md` overrides global `~/.kernary/agent.md`. The embedding provider catalog and credentials are global, while memory/vector databases stay under each project's `.harness/` and are protected by local Git excludes.

Both `kernary -r` and `/session` use an Up/Down, Enter-to-resume, Esc-to-cancel picker instead of numeric input. The UI exposes stable eight-character aliases such as `#7ac91e2f`; aliases work with `-r` and `/session`, while full internal IDs remain unchanged for durable storage and existing fork lineage.

All 30 built-in agents use versioned deep profiles with role-specific missions, non-goals, required inputs, SOPs, output/evidence contracts, failure escalation, context/tool/memory policies, model budgets, and public methodology sources. `/agent <id>` exposes the profile and source list without injecting the full catalog into model history.

Agent turns use target budgets with bounded automatic extensions rather than one fixed quality deadline. Finalization turns disable new tools and require either a complete result or an explicit partial handoff. Partial output and model continuation are stored durably before retry or failure. A repeated-tool stuck detector blocks the third identical call and requests a strategy change. Balanced mode defaults to three active subagents across the tree.

Cache Affinity ABI v2 keeps role profiles, project rules, and deterministic tool schemas in a stable prefix while moving task IDs, dependency evidence, retrieval results, and user input to the dynamic tail. OpenAI Responses receives a stable `prompt_cache_key` (plus native GPT-5.6 options), while Anthropic Messages uses explicit system/tool caching and automatic conversation caching. Concurrent agents with the same model/profile/tool ABI wait only until the cache leader's response starts, then continue in parallel. The footer permanently shows the provider-reported prompt-cache rate (`--` before the first request, then color coded); `/cache` exposes full read/write totals.

Grounded Hybrid Context Compaction v3 runs a preflight check for single-agent, team, adaptive, evidence, and review workflows. At 80% context usage it checkpoints first, preserves goals/tasks/pins/constraints/decisions/errors/exact data and complete tool pairs verbatim, then atomically swaps the Context Series only when Token usage decreases. A configured text model must return strict structured state with valid citations to real Context IDs; invalid, incomplete, secret-bearing, or unavailable model summaries fall back to local extractive evidence. When embeddings are configured, a bounded semantic rerank preserves a few old goal-relevant items verbatim; otherwise the same pipeline remains fully functional with lexical selection. Compaction summaries become project-local searchable memory, while the immutable transcript is never deleted.

With an embedding provider configured, vectors become a project-intelligence layer. Kernary automatically preserves high-value requirements, architecture, decisions, lessons, verification evidence, and failures; repository path/FTS/symbol/import/LSP candidates are semantically reranked, with structural seed files covering natural-language queries that have no literal hit. Query and unchanged-file vectors are cached by generation and content hash across agents, sessions, and process restarts, while batch embedding reduces activation round trips. The main agent and every subagent wave receive source-attributed retrieval data under a hard 1,800-token budget. `/vector status` reports coverage, cache reuse, degradation, injected evidence, rank promotions, and knowledge writes.

Spawned commands default to an OS-enforced `workspace-write` sandbox. Windows uses a restricted primary token, capability ACLs, a private desktop, and a Job Object; Linux uses bubblewrap namespaces and fails closed when no trusted `bwrap` is available. `/sandbox` reports the exact backend and network strength. `read-only`, explicitly confirmed network access, and explicitly confirmed `danger-full-access` are available without conflating sandbox boundaries with approval policy.

The package installs a native binary selected by npm for Windows x64 or Linux x64 glibc. It does not download executables during `postinstall`.
